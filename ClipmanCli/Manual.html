Clipman CLI

Development preview: this build is available for practical testing and feedback. Command names, configuration details, and behavior may change before the first stable CLI release.

Clipman CLI is an additional command-line client for Clipman text history. It does not replace the Windows, macOS, Android, or iOS apps. It is intended for terminals, SSH sessions, scripts, headless systems, and users who prefer ordinary text commands.

Clipman CLI connects to Clipman Server and reads and writes the same encrypted text-history database as the other clients. Clipman Server requires a nonblank, preferably unique history password. File history, Secrets, local clipboard monitoring, and server administration remain in the relevant apps or server tools.

Quick Start

Choose the binary matching the current operating system and processor. It is standalone and does not require Go to be installed. You may rename that binary to clipman-cli or clipman-cli.exe and place it on the command search path. The Windows binary requires Windows 10 or later; the graphical Clipman client remains available for Windows 7.

Run initialization once for each configuration. The easiest method is to use the private importable connection file created by Clipman Server:

clipman-cli init --connection-file clipman-server-connection.clpconf

For a direct private-CA HTTPS server, a current connection file also contains the public authority. The CLI validates it, binds it to the file's HTTPS host, and uses it as the exclusive trust anchor for that profile. No operating-system certificate installation or first-connection trust prompt is required. Treat the connection file as a credential because it also contains the server token.

Running clipman-cli init without --connection-file, --token, --token-file, or --server on a controlling terminal first asks Do you have a Clipman Server connection file (.clpconf)? [y/N]. Answering y prompts for the path to that file and continues exactly as --connection-file would. Answering n, pressing Enter, or running with --non-interactive skips the question and prompts for the server address and token individually instead.

If the server uses HTTPS with a private authority that init does not already trust, and neither --ca-cert nor --insecure was used, it shows the server certificate details and the Authority SHA-256 fingerprint, then asks Trust this certificate for this server? [y/N]. Compare that authority fingerprint with the one shown by the Clipman Server administrator before answering y. Trusting it stores the public authority in the configuration file so later commands do not ask again. Hostname mismatches, expired certificates, and other invalid certificates are rejected rather than offered as trust exceptions. Running with --non-interactive skips the prompt and reports the original error.

After the history password is entered and --save-password was not given on the command line, init asks Save the history password in the configuration file so it is not requested again? [y/N]. Answering y behaves like --save-password config, so later commands no longer prompt for the password; answering n, pressing Enter, or running with --non-interactive behaves like the default --save-password none. See Security for what "saved" means on each operating system before answering y.

Initialization checks the server and, when the selected database already exists, verifies that the history password can decrypt it. If the selected database does not exist, Clipman cannot distinguish a new password from a mistyped password. It warns before any history is created.

Add and retrieve text through standard input and standard output:

printf '%s' 'Text from a terminal' | clipman-cli put
clipman-cli get
clipman-cli get --name deploy-command > command.txt

Global Options

OptionPurpose
--config PATHUse a particular configuration file.
--server URLOverride the configured server for this command.
--password VALUESupply the history password. Prefer the no-echo prompt or a carefully managed environment variable because command arguments can be visible to other software.
--ca-cert FILETrust an additional PEM-encoded public authority or self-signed certificate while retaining the operating system's normal certificate authorities. When used with init, the public certificate is copied into the profile.
--insecureDisable HTTPS certificate verification for the selected server. This is an explicit last resort for a trusted private network; it prints a warning and must not be used across an untrusted network.
--jsonProduce structured JSON where the selected command supports it.
--quiet or -qSuppress nonessential status messages. Security warnings remain visible.
--verboseWrite diagnostic messages to standard error: the configuration file in use, the server address, the short history-bucket fingerprint, and the revision and entry count of each download. It never writes the token, the history password, or the full database identifier. --quiet takes precedence.
--versionShow the CLI version.

Global options must appear before the command. --ca-cert and --insecure are mutually exclusive. Prefer --ca-cert because it keeps certificate and hostname verification enabled.

Commands

CommandPurpose
initConfigure and test a server profile. Supports connection files, token files, a machine name, and non-interactive setup. Without a connection file or token on the command line, it interactively asks whether to read one from a file before falling back to entering the server address and token individually.
statusCheck the server and selected history. Add --refresh to download and decrypt the database.
listList entries. Filter by group, search text, or kind; use --json or --porcelain for scripts.
getWrite one entry to standard output. Template variables resolve unless --raw is used.
putAdd UTF-8 text from standard input, --file, or --text. Standard input avoids exposing text in the process list.
rmDelete exactly one entry and create the same synchronization tombstone used by Clipman desktop.
pickShow a numbered accessible list on the controlling terminal and write the chosen entry only to standard output.
menuBrowse history for viewing, searching, paging, outputting, adding, and deleting entries. This is what runs when you give no command at all. It opens the line interface or the full-screen interface according to your configuration; see Choosing a renderer.
syncDownload and validate current server history. This stateless edition has no offline write queue.

Run clipman-cli --help or clipman-cli COMMAND --help for the current syntax. Global options must precede the command. Command options follow it.

Selecting Entries

get and rm accept a visible zero-based index, exact ID, exact name, or text search. Indices belong to the selected view and can change after another client updates history. Scripts should prefer exact IDs or names.

clipman-cli get 3
clipman-cli get --id 0123456789abcdef0123456789abcdef
clipman-cli get --search kubectl --first
clipman-cli rm --name old-command --yes
clipman-cli get 3 --json
clipman-cli rm 3 --yes

Command options may be written before or after the index, so get 3 --json and get --json 3 are equivalent. To select an entry whose name or search text begins with a hyphen, put -- before it.

An ambiguous search is not treated as bulk deletion. Use a unique ID or a reviewed visible index.

Clipman CLI preserves optional HTML and RTF fields created by Windows or Mac Rich Text history when it reads, merges, and writes shared entries. CLI output remains the authoritative plain-text fallback and does not emit rich clipboard formats.

Interactive Use

Run clipman-cli menu, or run clipman-cli without arguments in an interactive terminal. Each row is a complete sentence naming the entry, its group, the device it came from, and how long ago it was used, so a row read on its own makes sense without column headings.

Choosing a renderer

Two renderers are available and both describe entries with the same words.

  • Line is the default. It prints numbered rows and reads typed commands, and avoids full-screen cursor movement entirely.
  • Full screen draws a scrolling list with arrow-key navigation, a live filter, and a preview of the selected clip.

Select one with --renderer line or --renderer tui, or the shorthands --line and --tui. Setting renderer in the configuration file changes the default; an option on the command line always wins.

Clipman does not try to detect a screen reader. No portable way to do that exists, and guessing wrong would silently change how the program behaves, so the choice is yours to make and the line renderer remains the default. If a terminal cannot run the full-screen interface, Clipman says so and names --renderer line rather than quietly switching, because the two renderers do not put the same things in the same places.

Because the choice is yours, each interface says which one it is. The line interface opens with Clipman line interface. Type ? for commands., and the full-screen interface names itself on its status line. In both, ? describes the other interface. clipman-cli status reports the configured one as Interface:, which answers the question without opening either.

Switching interface while you work

Press u in either interface to move to the other one. You are asked to confirm first: the full-screen interface takes over the whole window, and in it u is a single key with no Enter behind it, so a stray press should not be able to rearrange your screen. In the line interface answer yes; in the full-screen interface press y.

The switch carries your place across. The entry you were resting on, the search you had typed, and the history-or-templates view you had selected all travel with you, so the interface you arrive in is showing the same thing you left. In the full-screen interface the cursor lands directly on the row you were on; the line interface has no cursor to land, so it says You were on entry 12. after the list instead.

The history already downloaded is handed to the interface being started, so switching does not wait on the network. The choice is also written to your configuration file, so the next run opens where this one ended. If that file cannot be written, Clipman says so and switches anyway; a preference that could not be saved is not worth losing your session over. If the terminal cannot run the full-screen interface, Clipman says so and leaves you where you are, without changing anything.

pick refuses to switch. It offers one choice and exits, so switching out of it would strand you in a picker you could not switch back from.

Menu commands

  • Type an entry number to view it.
  • Type o, a space, and an entry number to write that entry to standard output and exit.
  • Type d, a space, and an entry number to delete it after confirmation.
  • Type / followed by text to show only matching entries. The text may contain spaces.
  • Type / on its own to clear the search.
  • Type n for the next page or p for the previous page.
  • Type a to add a new clip.
  • Type r to reload from the server.
  • Type u to switch to the full-screen interface. You are asked to confirm first, because it takes over the whole window. ui and renderer do the same thing.
  • Type ? for the command list, or q to quit.

The history is downloaded once when the menu opens and reused for every command afterward, so moving through the list never waits on the network. Deleting or adding an entry updates the list in place. Type r when you want to pick up changes made on another device.

Entry numbers are positions in the current filtered list rather than in the current page, so a number you heard stays valid after paging. While a search is active the numbers refer to the matches, and clearing the search restores the full numbering.

Adding a clip from the menu

a reads a clip over as many lines as you need. Finish with a single period on a line by itself. To store a line that holds only one period, type two periods instead. To abandon the clip without storing it, type !cancel on a line by itself. Clipman then offers an optional name; press Enter to skip it. The new clip joins whichever kind you are browsing, so adding one under --kind templates creates a template.

How much is announced at once

-n COUNT sets how many entries are announced at a time; the default is 20. Every entry remains reachable by paging with n and p. Use --all to announce the whole list at once without paging. This applies to the line renderer; the full-screen renderer scrolls to fit the window.

pick presents a numbered list, takes one choice, and exits. It accepts n and p to page and q to cancel. Prompts use the controlling terminal, so piped clip text remains separate.

The full-screen renderer

Run clipman-cli menu --tui. The list scrolls, a preview of the selected clip sits below it, and a status line reports what just happened.

Where the cursor goes

One rule decides it: the cursor sits in whatever you are moving through or typing into, because a screen reader reads the line the cursor is on.

  • While you move through the list, the cursor rests on the selected row, in the space just after the entry number, so each arrow key reads out the entry that is now selected. It never rests on the status line while you are browsing.
  • When Clipman asks a question, the cursor moves to the end of your answer on the same line as the question. Typing an entry number reads as Go to entry number: 12, so you hear both what was asked and what you have typed so far.

The selected row is also marked with -> in the text itself, and unselected rows are indented to match. A highlight that only changed colours would tell a screen reader nothing, and would be lost in review-mode navigation.

The heading, status line, and preview of the selected clip sit above the list, and the list runs to the bottom of the window. That ordering is deliberate: a terminal receives a redrawn screen from top to bottom, so keeping everything else above the list means the entry rows are the last text written, and a screen reader that reads newly written text finishes on the row you moved to rather than on the status line.

Clipman also redraws as little as it can, because everything redrawn is sent to the terminal again and therefore read again. Moving through the list changes only the two -> markers and the preview line; the entry text, heading, and status line are left alone. The selected row is not highlighted in reverse video for the same reason — a colour change across a whole row would resend every character of it on each arrow key, so only the marker is highlighted. Paging and scrolling have to repaint the list, and after they do the cursor returns to the selected row.

As in the line renderer, only Enter writes to standard output, so clipman-cli pick --tui | ssh web-02 'cat > /tmp/snippet' still transfers the clip and nothing else. The terminal is restored on exit, including if the interface stops unexpectedly.

Templates

Use put --template to create a template entry. get, pick, and menu output resolve the established Clipman date, time, time-zone, operating-system, and username variables. get --raw returns the stored text unchanged. Unknown variables remain unchanged.

clipman-cli put --text '{{year_full}}/{{month_num_padded}}/{{day_of_month_padded}}' --template --name today
clipman-cli get --kind templates --name today

Streams and Scripts

Successful get and pick commands write only clip text to standard output. Prompts and status messages do not enter the data stream. Text must be valid UTF-8 and may contain NUL bytes, whitespace, CRLF, LF, or no final newline.

--newline adds one LF only when the selected text does not already end in LF. --json provides structured output where documented.

Configuration

Where the configuration lives

Clipman CLI looks for config.toml in this order and uses the first it finds:

  1. the path given to --config;
  2. the path in the CLIPMAN_CONFIG environment variable;
  3. config.toml inside the directory named by CLIPMAN_HOME;
  4. config.toml sitting beside the clipman-cli program, if one is there;
  5. the per-user location: %LOCALAPPDATA%\Clipman CLI\config.toml on Windows, ~/.clipman/config.toml elsewhere.

Keeping settings beside the program

Step 4 lets one copy of Clipman CLI keep its own settings. On an interactive run, init asks:

Settings are normally saved for your user account, where every copy of Clipman CLI shares them.
Save them beside this program instead, so only this copy uses them? [y/N]

Answering y writes the configuration next to the program; that copy then uses it automatically. Two builds in two directories can point at two different servers without interfering, which is useful when testing a new version against a spare server while the installed one keeps working.

init --portable does the same without being asked, for scripts and --non-interactive runs. The question is skipped when --config, CLIPMAN_CONFIG, or CLIPMAN_HOME has already named a location.

The file is adopted only if it already exists, so an ordinary installation is unaffected and the per-user location remains the default. Answering the question or passing --portable is the only way to create one, because creating it should be deliberate.

Clipman looks beside the program, not in the directory you happen to be working in. A configuration file names a server and carries a token, so an unrelated config.toml in some other folder must never quietly take over a session.

Run clipman-cli status to see which configuration is in use; it is the first line of the report and appears as config_path under --json. --verbose also reports it.

The default configuration file is ~/.clipman/config.toml on Linux and macOS, and %LOCALAPPDATA%\Clipman CLI\config.toml on Windows. CLIPMAN_HOME changes the data directory. CLIPMAN_CONFIG or --config selects a particular config file.

The nonblank history password is resolved from --password, CLIPMAN_PASSWORD, saved configuration when explicitly enabled, or a no-echo controlling-terminal prompt. This allows clip text to be read from standard input without consuming the password prompt.

Security

  • Encrypted CLIPDB2 data is authenticated before decryption or decompression.
  • Database, JSON, nesting, entry-count, and text-size limits are enforced.
  • Server tokens, passwords, full database IDs, and clip text are not written to diagnostic output.
  • On Windows, saved token and password values are encrypted with DPAPI for the current Windows user. On Linux and macOS there is no equivalent encryption yet: saving the password (via --save-password config or answering y to init's save-password prompt) writes it in plain text into the owner-only configuration file (directory mode 0700, file mode 0600) — it is protected only by file permissions, readable by that user account or root.
  • --password, --token, and --text can be visible to other software inspecting the process list. Prefer prompts, environment variables used carefully, token files, connection files, standard input, or --file.
  • clipman:// is a convenient name for plain HTTP. Use it only on loopback, a trusted private network, or a VPN. Use HTTPS across an untrusted network.
  • Keep the Clipman Server token private. Delete or secure its connection-details file after configuring clients.
  • init's certificate-trust prompt is trust-on-first-use, the same model as an SSH host-key prompt: it protects against a passive eavesdropper but not against an attacker intercepting that first connection. Always compare the displayed authority fingerprint against the authority fingerprint shown by the Clipman Server administrator.
  • A private authority imported from a current .clpconf file is host-bound and exclusive to that server profile. --ca-cert remains an additive manual option for older setups. --insecure disables certificate and hostname verification and should be used only as a temporary last resort.

Exit Codes

CodeMeaning
0Success
1Local input, output, or data-format failure, and anything not covered below
2Usage, selection, or confirmation error
3Configuration, permission, or server-authentication error
4Network, TLS, or server failure, including timeouts, unreachable servers, and HTTP 413 or 5xx
5History password required, incorrect, or database authentication failed
6Requested entry or database not found
